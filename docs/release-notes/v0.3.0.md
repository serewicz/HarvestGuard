## HarvestGuard v0.3.0 — Validation, Trust, and First External Use

HarvestGuard is an open-source cryptographic asset inventory and
evidence-collection tool for technology due diligence. v0.3.0 is a **pre-1.0
trust release** focused on making first evaluation and the evidence behind it
easier to inspect. It adds no scanner or detector capability.

### What changed

- An operator-driven Phase 1 validation harness provides eight explicit human
  gates, bounded generators, frozen manifests, result schemas, dry-run support,
  and validation-local self-tests.
- Committed Ubuntu and AlmaLinux reports, sanitized AlmaLinux transcripts, a
  concise examples index, and an executive-readable summary show what the
  harness produced and keep observed fact distinct from scanner inference and
  interpretation.
- Stage 7 now normalizes missing rule IDs consistently across pandas missing
  value shapes and durably records summarization failures without hiding the
  completed scanner invocation statuses.
- The README presents an ordered evaluation path, including Debian/Ubuntu PEP
  668 guidance that recommends `pipx` for normal CLI use and keeps the safe demo
  corpus on the repository-clone path.
- Four pilot feedback forms request useful, sanitized context without asking
  reporters to disclose real secrets or confidential scan material.

### Evidence boundary

- Ubuntu was exercised on Ubuntu 24.04.4 LTS x86_64 in a Hyper-V VM. Its
  committed evidence is a report; no Ubuntu transcript is committed. This was
  not a Debian stable run.
- AlmaLinux was exercised on AlmaLinux 9.8 x86_64 in an OCI container, not
  directly on RHEL, Rocky Linux, or CentOS Stream. Its completed historical run
  used pandas below 3.0. The committed halted transcript records the fresh
  pandas 3.x Stage 7 defect later fixed under #140.
- `age_encrypted` was skipped where `age` was unavailable.
- Only `--type crypto` was exercised. Non-x86_64 systems, FIPS mode, Windows,
  WSL, other distributions, and broader scan modes remain unvalidated unless a
  linked artifact says otherwise.

### Install and evaluate

```bash
python -m pip install harvestguard==0.3.0
harvestguard --version
harvestguard scan /path/you/are/authorized/to/scan --type crypto --summary
```

On newer Debian and Ubuntu systems governed by PEP 668, use `pipx install
harvestguard` for normal CLI installation rather than
`--break-system-packages`. The synthetic demo is repository content and is not
included in the wheel or source archive; follow the
[README evaluation path](https://github.com/serewicz/HarvestGuard/blob/v0.3.0/README.md#quickstart)
to clone and run it safely.

### What this release does not claim

A finding is bounded evidence from the input and scan mode used. This release
does not claim complete inventory or format support, production readiness,
compliance, quantum readiness, exploitability, runtime exposure, remediation
priority, business risk, or absence of cryptographic material. Windows and WSL
are neither validated nor claimed supported.

Support remains best effort through GitHub Issues, with no SLA or guaranteed
response time. Report vulnerabilities privately as described in
[SECURITY.md](https://github.com/serewicz/HarvestGuard/blob/v0.3.0/SECURITY.md).
Scan only targets you are authorized to scan.
